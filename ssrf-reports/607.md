## Title

Server-Side Request Forgery (SSRF) Leading to Local File Read via `Add External Content` Feature

## Vulnerability Type

Server-Side Request Forgery (SSRF)

## Summary

The application accepts user-controlled URLs in the `Add External Content` feature and performs server-side requests to retrieve external resources for document generation.

By supplying a `file://` URI, the backend server accesses local files and returns their contents in the preview response.

The vulnerability was confirmed by reading the `/etc/passwd` file from the server.

## Vulnerable Endpoint

```http id="8zjlj4"
https://kzlabs.in/607.php
```

### Vulnerable Parameter

```http id="pgh34q"
External Content URL
```

## Steps to Reproduce

1. Navigate to the Invoices page.
2. Locate the **Add External Content** feature.
3. Select **Company Logo** as the content type.
4. Enter the following value in the URL field:

```text id="6m5l25"
file:///../../../../../../etc/passwd
```

5. Click **Fetch & Preview**.
6. Observe that the application retrieves and displays the contents of the local file.
7. This confirms that the application processes arbitrary URI schemes and allows access to local files on the server.

## Payload Used

```text id="xlg9ur"
file:///../../../../../../etc/passwd
```

## Impact

* Disclosure of sensitive server files
* Exposure of application configuration files
* Leakage of credentials, API keys, and secrets
* Information disclosure about the underlying operating system
* Potential escalation into further attacks against the application infrastructure

## Recommendations for Fix

* Allow only `http://` and `https://` URL schemes
* Block access to `file://` and other non-HTTP protocols
* Implement strict server-side URL validation
* Prevent local file access through URL handlers
* Restrict outbound requests to approved destinations only
