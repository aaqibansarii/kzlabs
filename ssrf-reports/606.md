## Title

Server-Side Request Forgery (SSRF) via `Metadata URL` Parameter

## Vulnerability Type

Server-Side Request Forgery (SSRF)

## Summary

The application accepts user-controlled input in the `Metadata URL` field and performs a server-side request to the supplied destination.

By providing an arbitrary URL, the backend fetches the resource and returns the response content to the user.

The vulnerability was confirmed by supplying an external URL and observing that the server successfully retrieved and displayed the response.

## Vulnerable Endpoint

```http id="8zjlj4"
https://kzlabs.in/606.php
```

### Vulnerable Parameter

```http id="pgh34q"
Metadata URL
```

## Steps to Reproduce

1. Navigate to the Instances page.
2. Locate the **Fetch Instance Metadata** feature.
3. Enter the following URL in the **Metadata URL** field:

```text id="6m5l25"
http://134.122.126.74
```

4. Click **Fetch**.
5. Observe that the application performs a server-side request and displays the response content.
6. This confirms that the application fetches user-supplied URLs from the server.

## Payload Used

```text id="xlg9ur"
http://134.122.126.74/phmyadmin
```

## Proof of Concept

The application successfully retrieved content from the supplied URL and returned an HTTP 200 response.

```http id="m5r7f2"
HTTP 200 OK
```

The fetched HTML content was displayed within the application interface.

## Impact

* Server-side requests to arbitrary destinations
* Potential internal network enumeration
* Access to internal services not intended to be exposed externally
* Increased attack surface for cloud and infrastructure environments

## Recommendations for Fix

* Restrict requests to approved destinations only
* Implement a strict allowlist of trusted hosts
* Block requests to localhost, loopback, and private IP ranges
* Validate and normalize all URLs before processing
* Disable unnecessary server-side fetching of user-supplied URLs
