## Title

Server-Side Request Forgery (SSRF) Leading to Local File Read via `Link URL` Parameter

## Vulnerability Type

Server-Side Request Forgery (SSRF)

## Summary

The application accepts user-controlled input in the `Link URL` field and fetches the supplied resource to generate a preview.

By supplying a `file://` URI, the backend server accesses a local file and returns its contents within the preview response.

The vulnerability was confirmed by reading the `/etc/passwd` file from the server.

## Vulnerable Endpoint

```http id="8zjlj4"
https://kzlabs.in/602.php
```

### Vulnerable Parameter

```http id="pgh34q"
Link URL
```

## Steps to Reproduce

1. Navigate to the Compose page.
2. Enter the following value in the **Link URL** field:

```text id="6m5l25"
file:///etc/passwd
```

3. Click **Generate Preview**.
4. Observe that the application generates a preview and displays the contents of the local file.
5. This confirms that the application processes arbitrary URI schemes and allows access to local files on the server.

## Payload Used

```text id="xlg9ur"
file:///etc/passwd
```

## Proof of Concept

The application reads and returns the contents of the local file:


## Impact

* Disclosure of sensitive server files
* Information leakage about the underlying operating system
* Exposure of configuration files and credentials
* Potential chaining into further attacks against internal infrastructure

## Recommendations for Fix

* Allow only `http://` and `https://` URL schemes
* Block access to `file://` and other non-HTTP protocols
* Implement strict server-side URL validation
* Restrict outbound requests to approved destinations only
