## Title

Server-Side Request Forgery (SSRF) via IPv4-Mapped IPv6 Address Bypass in `Add & Scan Link` Feature

## Vulnerability Type

Server-Side Request Forgery (SSRF)

## Summary

The application attempts to restrict access to internal IP addresses during URL scanning. However, the protection can be bypassed using an IPv4-mapped IPv6 address.

By supplying an IPv4-mapped IPv6 representation of the localhost address, the application performs a server-side request to an internal service and returns the response content.

The vulnerability was confirmed using the localhost address `127.0.0.1` encoded as an IPv4-mapped IPv6 address.

### Vulnerable Parameter

```http id="pgh34q"
Add & Scan Link
```

## Steps to Reproduce

1. Navigate to the Campaign Editor page.
2. Enter the following value in the **Add & Scan Link** field:

```text id="6m5l25"
http://[::ffff:127.0.0.1]
```

3. Click **Scan Link**.
4. Observe that the application marks the URL as safe and performs the request.
5. The response from the internal service is returned and displayed in the scan results.
6. This confirms that internal network restrictions can be bypassed using an IPv4-mapped IPv6 address.

## Payload Used

```text id="xlg9ur"
http://[::ffff:127.0.0.1]
```

## Impact

* Access to internal services not exposed externally
* Bypass of SSRF protection mechanisms
* Internal network enumeration
* Access to sensitive administrative interfaces
* Potential pivoting into internal infrastructure

## Recommendations for Fix

* Normalize and resolve all IP address formats before validation
* Block requests to localhost, loopback, private, and internal IP ranges
* Validate both IPv4 and IPv6 representations
* Re-resolve hostnames after redirects and before making requests
* Implement strict outbound request allowlists
