## Title

Server-Side Request Forgery (SSRF) Leading to Local File Read via `Service Endpoint URL`

## Vulnerability Type

Server-Side Request Forgery (SSRF)

## Summary

The application accepts user-controlled input in the `Service Endpoint URL` field and performs a server-side health check against the supplied resource.

By supplying a `file://` URI, the backend server accesses a local file and returns its contents in the response.

The vulnerability was confirmed by reading the `/etc/passwd` file from the server.

## Vulnerable Endpoint

```http id="8zjlj4"
https://kzlabs.in/603.php
```

### Vulnerable Parameter

```http id="pgh34q"
Service Endpoint URL
```

## Steps to Reproduce

1. Navigate to the Services page.
2. Enter the following value in the **Service Endpoint URL** field:

```text id="6m5l25"
file:///etc/passwd
```

3. Click **Check Now**.
4. Observe that the application performs the health check and displays the contents of the local file.
5. This confirms that the application processes arbitrary URI schemes and allows access to local files on the server.

## Payload Used

```text id="xlg9ur"
file:///etc/passwd
```

## Proof of Concept

The application reads and returns the contents of the local file:


## Impact

* Disclosure of sensitive server files
* Information leakage about the underlying operating system
* Exposure of configuration files and credentials
* Potential chaining into further attacks against internal infrastructure

## Recommendations for Fix

* Allow only `http://` and `https://` URL schemes
* Block access to `file://` and other non-HTTP protocols
* Implement strict server-side URL validation
* Restrict outbound requests to approved destinations only
