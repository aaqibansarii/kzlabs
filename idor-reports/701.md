# Insecure Direct Object Reference (IDOR) Leading to Unauthorized Access to Other Users' Order Details

## Vulnerability Type

Insecure Direct Object Reference (IDOR)

## Summary

The application allows authenticated users to access order details belonging to other users by modifying the value of the `id` parameter in the request.

By changing the order identifier, an attacker can view sensitive information associated with orders that do not belong to their account.

## Vulnerable Endpoint

```http
https://kzlabs.in/701.php?action=order&id=46
```

### Vulnerable Parameter

```http
id
```

## Steps to Reproduce

1. Log in to the application.
2. Navigate to the **My Orders** section.
3. Open any order and intercept the request using Burp Suite.
4. Observe the request:

```http
GET /701.php?action=order&id=46 HTTP/1.1
Host: kzlabs.in
```

5. Change the value of the `id` parameter to another valid order ID:

```http
GET /701.php?action=order&id=40 HTTP/1.1
Host: kzlabs.in
```

6. Forward the modified request.
7. Observe that order information belonging to another user is returned.

## Proof of Concept

The application discloses order details belonging to another user after modifying the order identifier from `46` to `40`.

After changing the parameter to `id=40`, the application returns order **SC-5028** belonging to another user and discloses:

* Username
* Email Address
* Shipping Information
* Payment Information
* Tracking Details
* Order Information

without verifying ownership of the requested order.

## Impact

* Unauthorized access to other users' order information
* Exposure of sensitive customer information
* Disclosure of email addresses
* Exposure of shipping and tracking details
* Violation of user privacy

## Recommendations for Fix

* Implement proper server-side authorization checks.
* Verify ownership of orders before returning data.
* Enforce object-level access control for all order-related endpoints.
* Use unpredictable identifiers instead of sequential numeric IDs.
* Deny access to resources that do not belong to the authenticated user.
