# Insecure Direct Object Reference (IDOR) Leading to Unauthorized Access to Other Users' Trip Details

## Vulnerability Type

Insecure Direct Object Reference (IDOR)

## Summary

The application allows authenticated users to access trip details belonging to other users by modifying the value of the `id` parameter in the request.

An attacker can enumerate valid trip identifiers and retrieve sensitive trip information associated with other users without proper authorization checks.

## Vulnerable Endpoint

```http
https://kzlabs.in/702.php?action=trip&id=11
```

### Vulnerable Parameter

```http
id
```

## Steps to Reproduce

1. Log in to the application.
2. Navigate to the **Trips** section.
3. Open any trip and intercept the request using Burp Suite.
4. Observe the request:

```http
GET /702.php?action=trip&id=11 HTTP/1.1
Host: kzlabs.in
```

5. Modify the value of the `id` parameter to another valid trip identifier:

```http
GET /702.php?action=trip&id=1 HTTP/1.1
Host: kzlabs.in
```

6. Forward the request.
7. Observe that the application returns trip details belonging to another user.

## Proof of Concept

The application discloses another user's trip information after modifying the trip identifier from `11` to `1`.

After changing the parameter to `id=1`, the application returns trip **#1** belonging to another user and discloses:

* Passenger Information
* Driver Information
* Vehicle Details
* Pickup Location
* Dropoff Location
* Trip Date
* Fare Information
* Tip Amount

without verifying ownership of the requested trip.

## Impact

* Unauthorized access to other users' trip information
* Exposure of sensitive user data
* Disclosure of travel history and trip locations
* Exposure of driver and vehicle information
* Violation of user privacy

## Recommendations for Fix

* Implement proper server-side authorization checks.
* Verify ownership of trips before returning data.
* Enforce object-level access control for all trip-related endpoints.
* Use unpredictable identifiers instead of sequential numeric IDs.
* Deny access to resources that do not belong to the authenticated user.
