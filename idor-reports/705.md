# Insecure Direct Object Reference (IDOR) Leading to Unauthorized Access to Other Users' Support Tickets

## Vulnerability Type

Insecure Direct Object Reference (IDOR)

## Summary

The application allows authenticated users to access support tickets belonging to other users by modifying the value of the `id` parameter in the request.

An attacker can enumerate valid ticket identifiers and retrieve sensitive support ticket information associated with other users without proper authorization checks.

## Vulnerable Endpoint

```http
https://kzlabs.in/705.php?action=ticket&id=2
```

### Vulnerable Parameter

```http
id
```

## Steps to Reproduce

1. Log in to the application.
2. Navigate to the **Support Tickets** section.
3. Open any support ticket and intercept the request using Burp Suite.
4. Observe the request:

```http
GET /705.php?action=ticket&id=2 HTTP/1.1
Host: kzlabs.in
```

5. Modify the value of the `id` parameter to another valid ticket identifier:

```http
GET /705.php?action=ticket&id=5 HTTP/1.1
Host: kzlabs.in
```

6. Forward the request.
7. Observe that the application returns support ticket details belonging to another user.

## Proof of Concept

The application discloses another user's support ticket information after modifying the ticket identifier from `2` to `5`.

After changing the parameter to `id=5`, the application returns support ticket **SUP-5** belonging to another user and discloses:

* User Information

* Support Ticket Content
* Internal Security-Related Information

## Impact

* Unauthorized access to other users' support tickets
* Exposure of sensitive customer information
* Disclosure of email addresses
* Exposure of account-related details
* Disclosure of potentially sensitive security information
* Violation of user privacy

## Recommendations for Fix

* Implement proper server-side authorization checks.
* Verify ownership of support tickets before returning data.
* Enforce object-level access control for all support-related endpoints.
* Use unpredictable identifiers instead of sequential numeric IDs.
* Deny access to resources that do not belong to the authenticated user.
