# Local File Inclusion (LFI) via Path Traversal in `file` Parameter

## Vulnerability Type

Local File Inclusion (LFI)

## Summary

The application fails to properly validate user-supplied input in the `file` parameter, allowing directory traversal sequences to be used to access files outside the intended directory.

An attacker can leverage this vulnerability to read arbitrary files from the server's filesystem, resulting in unauthorized disclosure of sensitive information.

## Vulnerable Endpoint

```http
https://kzlabs.in/904.php?file=../../../etc/os-release
```

### Vulnerable Parameter

```http
file
```

## Steps to Reproduce

1. Navigate to the vulnerable endpoint.
2. Observe that the application accepts a user-controlled `file` parameter.
3. Supply the following path traversal payload:

```http
../../../etc/os-release
```

4. Send the request.
5. Observe that the contents of the `/etc/os-release` file are returned in the response.

## Payload Used

```http
GET /904.php?file=../../../etc/os-release HTTP/1.1
Host: kzlabs.in
```

## Proof of Concept

The application successfully processes the path traversal payload and returns the contents of a local system file.

## Impact

* Unauthorized access to sensitive files
* Disclosure of server configuration information
* Exposure of application source code
* Leakage of credentials and secrets stored on the server
* Increased risk of further server compromise

## Recommendations for Fix

* Validate and sanitize all user-supplied file paths.
* Restrict file access to a predefined allowlist of permitted files.
* Prevent directory traversal sequences such as `../`.
* Use canonical path validation before accessing files.
* Implement proper access controls for sensitive resources.
